# Upload Security Review

This review captures the controls currently implemented for evidence uploads and the production hardening still required.

## Current Controls

- Uploads are restricted to PDF, JPEG, and PNG.
- File size is capped at 10 MB.
- File extension and browser-provided MIME type must agree.
- File signatures are checked before storage.
- File names are sanitized before being stored as display names.
- Storage object keys are generated by the app, not supplied by users.
- Local uploads are stored outside `public`.
- Evidence downloads go through authenticated application routes.
- Inline previews are limited to PDF, JPEG, and PNG.
- Evidence upload flows are rate limited per uploading user.
- Stored document metadata includes MIME type, size, checksum, storage provider, bucket, object key, and access level.

## Blocked By Design

The current upload validator rejects:

- HTML
- SVG
- JavaScript
- Office documents
- Arbitrary archives
- Empty files
- Files with mismatched extension, MIME type, or content signature

This is intentional. These document types can carry scripts, macros, external references, or browser-executable content.

## Production Hardening Still Needed

- Add virus and malware scanning before final acceptance.
- Move rate limiting from in-memory storage to Redis or another shared store.
- Add quarantine status for uploads awaiting malware scan results.
- Add admin quarantine review screens.
- Add storage lifecycle rules for old rejected uploads.
- Add provider-specific private object access for Vercel Blob and S3.
- Add audit events for rejected uploads and repeated upload-rate-limit hits.

## Review Rule

Any new upload flow must call the shared upload validator before storage, use random object keys, store metadata in `Document`, and serve files through an authenticated route.
